# 网站修改规则

继承 [DevOps AGENTS.md](../AGENTS.md)。开发命令、路由与组件约定见 [README.md](README.md)。

- 复用现有 Vue 组件、`style.css` 变量、`api.ts`、`auth.ts` 和 `repositoryUrl`，不引入第二套组件库、请求包装或 Token 存储。
- 仓库标签使用 `/code`、`/issue`、`/pr`、`/settings` 路径；详情为 `/issue/:number`、`/pr/:number`，PR 子页使用路径后缀。query 只保存筛选 / 代码位置；旧 `tab=settings` 仅作兼容跳转。支持刷新、后退和评论锚点。普通文件只做转义文本预览；README 使用共享 MarkdownDocument / markdown.ts，原始 HTML 关闭、链接重写后再经 DOMPurify 白名单清洗，不能直接注入原文或跳过清洗；新请求不能被旧响应覆盖。
- AppNotice 成功反馈使用 v-model 清理父级消息，默认 5 秒关闭；错误与持续状态不自动消失，定时器需在卸载时清理。复制等短反馈使用 placement="floating"，页面错误和持续状态使用默认 inline；浮层不能挤动页面或抢焦点。AppInput / AppSelect 旁的按钮使用 actions 插槽，保持标签和说明不参与按钮对齐。侧栏折叠状态仅存 UI 偏好，不存凭据。
- 保护开关复用 AppSwitch，由服务端保存成功后更新状态，失败保留已保存值；仅拥有者看到调整入口。
- 全站中文深色界面；用户可见文案描述动作和后果，不把镜像、数据库或内部 ID 等部署细节混入普通业务流程。
- DevOps 面向专业人员的桌面开发工作；界面开发与浏览器验收以电脑为目标，不安排手机适配或窄屏检查。
- 个人镜像管理与 repo Registry 页签共用镜像 / 标签和 namespace 创建组件；全站列表由服务端先做仓库 ACL 再计数 / 分页，账号及 namespace 切换后清除旧请求结果。
- 菜单和按钮依据当前权限显示，后端继续负责拒绝越权。不要把全局 admin 当作仓库管理员。
- 路由 / 所有者变化后刷新页面状态；数字仓库 URL 兼容入口和规范名称 URL 都要保留。不要因复用组件而展示上一个仓库的数据。
- 岗位、Git access、仓库管理资格分开；添加与编辑复用 `RepositoryMemberForm`，保留自定义岗位，非拥有者不发送 `is_admin`。
- 仓库列表的提交趋势必须来自 Git 数据，使用独立加载及错误状态，不以假数据填充；简介限两行并容纳无空格长文本。
- 仓库成员、设备列表、克隆地址和简介要容纳长内容；局部滚动 / 换行，避免整个页面溢出。保留表头、标题、分页可见性与一致边距。
- 确认弹窗、下拉框、展开区保留键盘操作、可访问名称、焦点恢复及 ARIA 状态。危险动作使用现有确认组件。
- `AppButton` 默认不是 submit；表单提交显式声明。busy 时禁用重复操作，失败显示可理解的信息。
- Issue / PR 编辑在原位置替换内容，保留明确的保存 / 取消和焦点返回。表单草稿复用 `useDraft`，按账号与具体编辑位置隔离；数据初始化后再恢复，提交成功或明确放弃才清除，网络错误不能丢草稿。版本号和行评论 SHA 随草稿保留，不能为恢复草稿绕过并发检查。
- 邮箱验证码流程使用共享组件和服务端 Retry-After，不输出验证码，不用真实 SMTP 做单测。
- 前端构建只在本地运行；不得把 Node.js 构建阶段或 `dist` COPY 加回 Gateway Dockerfile。

行为变更运行相关 Vitest 与生产构建；布局修改用构建及必要的真实浏览器检查验证。jsdom 的尺寸 / dialog 替身不能作为 Safari 视觉验收证据。依赖变更同步 `pnpm-lock.yaml`，不要提交 `dist/`、`node_modules/` 或 IDE 私有状态。

- Issue / PR Markdown 使用独立讨论渲染器，引用解析只能来自当前 ACL 下的 API 结果；不在代码、转义内容或已有链接内重复替换。审阅草稿、未发表附件不能暴露给其他成员。Issue 移交后的原正文引用需保持原仓库上下文。
