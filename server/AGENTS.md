# 后端修改规则

继承 [DevOps AGENTS.md](../AGENTS.md)。结构和命令见 [README.md](README.md)，迁移规则见 [migrations/README.md](migrations/README.md)。

## 修改前

- 阅读目标路由、schema、权限依赖、模型及相应测试，不只改页面请求对应的单个函数。
- 依赖变更使用 Python 3.14 / uv 并更新 `uv.lock`；Ruff 配置以 `pyproject.toml` 为准。
- API 响应继续显式挑选安全字段；不要序列化整个 ORM 用户、会话或配置对象。
- 登录设备接口在统计和分页前按真实会话有效条件过滤，本人和管理员入口保持一致；隐藏失效记录不意味着删除数据库历史。
- 网页会话续期保持数据库与浏览器 Cookie 一致，按分钟节流；持有会话行锁后重新检查时效、撤销、账号及密码版本。事务提交成功后才能发送续期 Cookie，保留 Token / CSRF 值以兼容已打开的标签页；退出、过期和吊销不能被续期恢复。覆盖正常 / 拒绝路径、并发、提交失败与直接 Response 响应。

## 必须保留

- 数据库会话实时校验、响应前提交、Cookie / Origin / CSRF 绑定；机器请求仅豁免 `/oauth/token`、`/oauth/revoke`、`/oauth/device/code` 精确 POST，`git_lfs.machine_request` 列出的 LFS 路径，`ci_api.machine_request` 的精确产物 PUT，以及通过 `bearer_user` 预校验的仓库 / 协作 API。CI 产物路由必须验证任务 Bearer 和实时执行权限；WebSocket 只接受 worker 凭据并拒绝浏览器 Origin。CLI Bearer 限定 `devops-cli`、api:read/write 和 `api_machine_path`，路由事务再次校验；无效 Authorization 不得回退 Cookie。用户资料 / 全局管理继续仅接受 Cookie。
- 验证码用途、用户绑定、单次消费、错误次数和 Redis 原子限流；失败审计 / 次数不能随意丢失。
- 邮件同时保留纯文本和 HTML，动态内容转义；装饰使用内联样式，不引入外部资源或跟踪。使用 SMTP 替身验证格式，真实发送需要已有明确授权。
- bcrypt 输入按原始 UTF-8 字节处理，8–72 字节；AES-GCM 使用随机 nonce、AAD 用户绑定和密钥版本。不要把兼容密码加入登录 API。
- admin 授权仅人工数据库维护；管理员不能代设用户兼容密码，不能通过普通角色接口授予 / 移除 admin。
- 仓库拥有者的归档 / 取消归档、移交和软删除，Cookie 与 CLI 请求均要求单次 `repository_operation` 邮箱验证码。复用现有邮件挑战和限流，验证码等待之后重查原会话或 CLI 授权；不得用旧登录或管理员用途验证码替代。
- 私有仓库访问独立于全局 admin。修改仓库、成员和生命周期时保持行锁和 `populate_existing` 重新读取，避免并发权限陈旧。
- 系统强制管理使用 `repository_admin.py` / `registry_admin.py` 的显式入口。写请求单次验证当前管理员的 `admin_operation` 邮件码，和业务修改在同一事务；验证失败计数需保留，审计不能含验证码。普通仓库成员变化也须推进仓库 `updated_at`，让管理表单检测并发修改。
- 新仓库在 main 上生成 README 初始提交，克隆地址取配置的可信 origin；构造对象不执行用户 Git 钩子，不记录用户真实邮箱，失败只清理本次新目录，不能重写已有历史。
- 仓库 ID 对应稳定 bare 目录，名称不能用于物理路径；软删除、归档和移交按现有语义处理。
- Code API 仅接受分支名、字面路径；读取解析出的对象 ID，限制对象大小；目录 README 从完整列表选择且固定同一提交，忽略符号链接；图片接口只返回有大小上限的 raster 格式，不能将 HTML / SVG 作为页面资源。不能检出文件、跟随 Git 符号链接、执行 textconv 或传入 shell。
- 两种保护只有拥有者可修改，行锁、审计和严格布尔校验必须保留；鉴权响应的策略头供网关钩子使用，不能信任客户端同名头。
- LFS 在 ID 仓库内隔离存储；流式临时上传必须验证 SHA-256 / 大小，结束时重新鉴权并锁仓库后原子发布。不得让任意 URL / Cookie 绕过成员关系，不要把整个大文件载入内存。备份 Git 目录同时备份其中的 LFS 数据。
- OAuth code 单次使用、S256、严格 loopback、refresh 轮换与重放撤销；不新增 Cookie / 兼容密码的 Git 回退。
- 授权列表过滤已撤销项时保留数据库历史，并在 limit 前过滤。只有成功刷新才能把授权续期至刷新后 30 天；持有授权行锁后重新检查到期时间，凭据轮换与续期同一事务提交，不恢复已过期或撤销的授权。提交趋势沿用仓库 ACL，用真实 Git 提交去重、UTC 分桶，保留读取上限 / 超时及错误状态。
- 新配置 key 同步默认值、完整校验、已有数据库的迁移与测试；不要靠新的环境变量掩盖数据库缺项。

## 迁移和验证

已存在的迁移用于复现历史结构，不重写它们实现新功能。模型变化新增顺序迁移；考虑旧数据、唯一约束、锁、失效授权和降级后的访问风险。不得自动伪造邮箱、丢弃记录或绕过降级保护。

使用本地隔离 schema、Redis 随机前缀和 `Mailbox`。权限变化至少验证拥有者、管理员、普通成员、无关系用户及并发 / 拒绝路径中的相关分支。运行相关 pytest、Ruff；跨模块调整再运行完整检查。Git 协议或路径变化还需真实 Gateway 集成测试。

不要为了检查而打印 `config` 敏感 JSON、raw Token、密码材料、验证码或数据库 DSN。测试失败输出和异常日志也需遵守相同边界。

## 协作修改边界

- Issue / PR 共用仓库行锁下的单调编号；跨仓库关系先取图锁，再按仓库 ID 排序加锁并刷新权限。子项单父节点、无循环、最多 100 个直接子项 / 8 层；关闭父项不级联。
- 审阅草稿、未发表附件、历史正文和引用解析均须校验访问权。发布后再建立提及 / 通知；移交保留原正文引用上下文，后续编辑使用当前仓库。
- 冲突检测、普通合并与 rebase 都用隔离的原生 Git，不能执行源仓库 config / hooks / 合并驱动。未知、失败、超时不得作为可合并。
- PR 合并必须检查当前用户，以及浏览器会话或独立 CLI 授权（两者恰有一个）、仓库策略、审批、checks 和两端 SHA；先存意图，原子引用事务写恢复标记，最后幂等提交 SQL。不得用重试覆盖新推送；`refs/devops/` 禁止客户端写入。
- 后台 worker 属于 server 发布范围，同镜像、同配置、同 Git 挂载。任务有租约 / 尝试次数，过期结果不能覆盖新任务；推送回执先入库后删除。测试至少覆盖真实 Git 合并、冲突、权限失效、私有草稿及 SQL 故障恢复。
